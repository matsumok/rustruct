## 2026-09-30 に決めたこと（要約。本文は `docs/design/README.md`）

### サイトの構成
- 個人サイト。**Tools**（構造計算）・**Data**（材料や規格の値。2026-10-14 に追加、`docs/adr/0005`）・**Studies**（数学やかたちの可視化）・**Notes**（文章）の四部構成
- サイト名はドメインそのもの `rustruct.matsumok.com`。`wordmark`（等幅 12px / 500）で、`.matsumok.com` はドットごと `muted`・400（2026-10-14 に dx serve で見て決定。`accent` にはしない）
- **箱で区切らず、余白と文字の大きさの差で組む。** 灰色の地に白いカードが並ぶ管理画面の型は避ける
- 住所で組む：各項目にパス（`/studies/pinwheel`）を `path` で添え、下層ページでは同じ住所が伸びる。**これがパンくずの代わり**
- 一覧は「名前＋一行＋パス」だけ。グリッドは2列まで
- 参照する温度感：takram、rsms.me、tylerxhobbs.com、Order

### 色（`tokens.json` の役割名）
- 地は `paper` 一色（ライト `#ffffff`）。`fill` は「書けない」と「図の下地」の2つの意味だけ
- 文字は `ink` と `muted` の2段。線は `line`（1px）、入力欄の枠は `line-strong`
- `ng`（Radix red-11 `#ce2c31`）は NG 判定と入力エラーだけ。警告は色を使わず「!」と文言
- 差し色 `accent` は indigo-9 `#3e63dd` の1色相。使う場所は3つに限る（今いるセクションの下線、新着の点、図の中の一か所）。プライマリーは `ink`（主ボタン・リンク・選択セルは墨）。面を塗る薄い段は `accent-soft`（トップの一文の句点は 2026-10-15 にやめた）
- ダークテーマは同じ役割名で切り替える。マークアップに色の値を書かない

### グラフの色
- 系列色は5色を先頭から順に：`chart-1` 琥珀（amber-11）、`chart-2` 青碧（cyan-9）、`chart-3` 墨（= `ink`）、`chart-4` 紅（ruby-9）、`chart-5` 青紫（violet-9）。6系列以上はグラフを分ける
- 色覚シミュレーション（Machado・Brettel）と 2px 線での見分けやすさ（Szafir）で総当たり検証済み。岡部・伊藤の約2倍の見分けやすさ。**8月の「indigo・cyan・orange・bronze」は廃止**
- 点の形も系列ごとに変える：● ■ ▲ ◆ ▼
- 一方向の濃淡（コンタ）は藍の `seq-1`〜`seq-12`。正負のある量は藍←灰→琥珀の `div-1`〜`div-12`（0 は div-6 と div-7 の境）
- 図の形は matplotlib 型：`ink` 1px の四辺の枠、内向きの目盛り、格子は既定で引かない。凡例は図の中8か所・外3か所・auto・none。スマホ幅では下
- 制限値の線は `muted` の破線。超過点だけ `ng` にして「NG」の文字を添える
- 2色塗り分け（風車タイリング等）は `accent` と `chart-2`
- wgpu で描くときも同じ sRGB 値を使う

### 文字
- 和文 IBM Plex Sans JP、数字・パス・サイト名 IBM Plex Mono（Google Fonts）
- 大きさは振れ幅で階層を作る：`display` 30px / `title` 22px は細く（300）、それ以外は 13px と 11px。中間を作らない。`figure`（56px / 300）はページの答え1つだけ
- 太字（500）は `heading` と `wordmark` だけ
- 数値は必ず `num`（等幅）で単位まで右揃え。Notes の本文だけ `prose`（15px / 28px）
- 文言は短く言い切る。「！」や絵文字は使わない。見出しは体言止め

### 余白と形
- `space-1`〜`space-8` = 4 / 8 / 12 / 16 / 20 / 28 / 40 / 48px。`space-0`（0）と、PC の計算のページの区切りの左右だけに使う `space-9`（80px）がある（2026-10-15、#23）。80 より大きい余白は使わない
- 角は `radius-0` が既定。`radius-8` はボタンとツールの入力カードだけ。`radius-full` は状態の点だけ
- 影、グラデーション、ぼかし、トランジションは使わない

### 図とアイコン
- Studies の図版は計算で描いた SVG。線は `ink` の細線、下地は `fill`
- アイコンは基本使わない（ヘッダーのボタンだけは使う。「画面幅」）。ロゴはない。サイト名は `wordmark` の文字で組む

## 8月から引き継ぐ規則（使い勝手の規則。9月の値で読み替える）

### 入力と表示の区別（最重要）
- 入力表は「データテーブル」ではなく**スプレッドシート**（`Sheet`）。格子は `line`、選択セルは `ink` の 2px 内枠
- 塗り＝書けない、枠＝書ける。書ける場所は `paper` の地に `line-strong` の枠。計算セル・行見出し・列見出しは `fill`
- 枠のある器は入力にしか使わない。読み取り専用の入力欄は使わない。結果の置き方は「列の単位と表」（2026-10-14 に ResultValue の下線から表の形へ変えた）
- 入力セルは大きく、表示用テーブルは小さく。表示用テーブルの行区切りは罫線（交互の背景色は不採用）（形は「列の単位と表」）
- 入力値を変えた瞬間に派生値（μs級）が更新される。重い解析は即時でなくてよい
- 全画面の再描画はしない。行を1つ足すときも部分更新
- Excel 連携は値のコピペができれば十分

### 列の単位と表（2026-10-14 に決めた。理由は `docs/adr/0006`）
- **本文の1単位は 335px**（tokens の `width-column`、`max-w-column`。2026-10-15 に 360px から変えた）。iPhone SE（第2・第3世代、画面 375px）の本文の幅で、表と図を収める約束の幅。スマホでは列を画面いっぱい（335〜400px）にし、単位は iPad 以上で列の幅になる。SE で確かめた表は、iPad・PC でも同じ幅で出る。表と図は1単位か2単位に収める
- iPad・PC では1単位の列を横に並べる。スマホでは縦に積む。計算のページは「入力＋結果」の列と「根拠」の列の2列
- 計算のページは **入力 → 結果 → 根拠** の順に置く。「入力」「結果」「根拠」という部の見出しと区切りは置かず、入力のすぐ下に結果を続ける。区切りは表や式の見出し（`heading`）で付ける
- **表示用の表は横罫だけ**。見出しの下と各行の下に `line` の 1px。`ink` の線は部の見出しの上だけ（デザインシステムの約束どおり。表の頭と尻に `ink` を引く案は退けた）。縦罫・塗り・交互の背景は使わない。入力の Sheet（格子＋`fill`）と一目で分ける
- 結果も同じ表の形で置く（入力のすぐ下、`space-6` 空けて）。ResultValue の下線は使わない
- 「入力＋結果」の列と、入力に依らない表や式の列の間には `line` の区切りを引く。区切りは列の外の独立した要素にし、iPad・PC では縦の線、スマホでは横の線。線の左右の空きは並べる親の間（`gap`）で決め、iPad `space-4`、PC `space-9`（80px。2026-10-15、#23。48・64・80・96 を並べて撮り、本人が 80 に決めた。右の列が左に線と余白を持つ形は、左右の空きが別々の所で決まり、列の中身を1単位に保つのに `box-content` が要ったのでやめた。PC の 16 は2列が真ん中に寄りすぎて見えた）。スマホの区切りの上下は `space-8`（2026-10-15）。表の行は約 40px なので、`space-7`（40px）では表の最後の罫の下にもう1行あるように見えた
- **単位は表の名前か列の見出しに括弧で書き、数字の後には付けない**（「許容応力度（N/mm²）」「γ（kN/m³）」）。単位の違う値を並べる結果は、値ごとに列を立てて見出しに書く。入力欄の名前も「Fc（N/mm²）」、入力の Sheet の見出しも「B（mm）」。ページの中で単位の置き場を散らさない
- 行の上下は `space-2`、セルの左右は `space-3`、表の端の列は端に寄せる。見出しは `label` の muted、先頭の列は左、数値の列は `num` で右揃え、式の列は `num` で左揃え
- 列見出しは折り返さず、改行は `br` で。数値の列の2行の見出しは、行どうしを左で揃えてまとまりを列の右に寄せる。列をまとめる見出し（「長期」「短期」）は中央に置いて下に `line`（まとまりごとに `space-3` 離す）。括弧書きを添える値（「215（*195）」）は括弧書きを隣の列に分け、括弧の外の数値を揃える。4桁以上の数は3桁ごとに「,」。小数の桁数が行で違う列は、足りない桁を数字幅の空白で埋めて小数点を揃える（2026-10-15）
- 表や式の名前は上に `heading`（太字・ink）で置く。11px の muted ではタイトルと分からないため。見出しと見出しの間は `space-7`
- 注記は下に `label` の muted の箇条で。出典は画面に出さない（コードのコメントと ADR に書く）
- 画面に出す値は計算に使うものだけ。コンクリートの単位体積重量は E の式で使う γ だけを出し、γ₁ は出さない
- 1単位に入りきらない表（列の多い表）は、その表だけ横にスクロールする

### 画面幅（2026-10-15 に決めた。理由は `docs/adr/0007`）
- スマホ・iPad・PC のそれぞれで美しく組むことを条件にする。切り替えは 2 段、レイアウトは 3 通り
- 切り替わる幅は **768px（スマホ → iPad）と 1024px（iPad → PC）**。Tailwind の名前は `md:` と `lg:`（既定と同じ名前・同じ値）。tokens.json に px で書き、既定の sm・xl・2xl は消す（rem にしないのは、文字を px で固定しているので幅だけ動いてもかみ合わないため）。Tailwind・Bootstrap・GitHub Primer で最も多い 768 と、990〜1070 に集まる PC の境から取った（Material 3 は 600 / 840、apple.com は 735 / 1069）
- 当たり方: iPad mini の縦（744）はスマホの組み方。iPad・Air・Pro 11" の縦（820〜834）は iPad の組み方で、335px の2列が入る。iPad Pro 13" の縦（1024）と iPad の横（1133〜1366）は PC の組み方
- 画面幅で大きさを変える文字は、大きな文字（`display`・`title`・`figure`）と Notes の本文（`prose`）だけ。本文・表・ラベル（13 / 11px）はどの幅でも同じで、列幅も変えない。大手の多くが本文を固定して大見出しだけ変える（Bootstrap の RFS は小さな文字を縮めない。apple.com も本文は同じ大きさ）。Notes は読みものなので、長文のサイトにならって本文も上げる。PC で全体を一段上げる案は、列幅と表を決め直すことになるので退けた
- 大きくするのは **768px から**（iPad・PC は同じ大きさ）。1つの役割の大きさは2つまで（「中間の大きさを作らない」）。値は約 1.2 倍で、大きさ / 行送りは display 36 / 48、title 26 / 36、figure 64 / 64、prose 17 / 32（スマホは 30 / 40、22 / 30、56 / 56、15 / 28）。1.35 倍の案は title がスマホの display と同じ大きさになるので退けた
- 画面は**ヘッダーと本文**に分ける。ヘッダーは上に固定し、スクロールするのは本文だけ。ヘッダーは左にサイト名（wordmark）、右にライトとダークの切り替え・アカウント（登録ユーザーのログイン）のボタンだけ。ページ名と四部（Tools / Data / Studies / Notes）のボタンはヘッダーに置かない（2026-10-15。#23 で「右にページ名」「中央に四部」と作ったが、ページ名は本人が頼んでいなかったので外し、四部も消した）。今いる場所は、サイト名の右に英語の住所をパンくずとして置く予定（スマホでは出さない。別の Issue）
- 本文の頭のパスとページの見出し（`title`）は残す。見出しと内容の間は `space-7`（2026-10-15。`space-3` では狭く見えたので、12・20・28・40 を撮り比べて本人が決めた。余白の段は増やさない）
- スマホのヘッダーは、サイト名を `rustruct` の文字だけに縮め、四部のボタンだけをメニューにしまう。ライトとダークの切り替えとアカウントはスマホでもヘッダーに残す（2026-10-15、#23 で直した。初めに「三つともメニューにしまう」と書いたのは本人の想定と違っていた）。メニューのボタンはサイト名の左に置く。ロゴは作らない（「ロゴはない」はそのまま）
- メニュー・ライトとダークの切り替え・アカウントなど、ヘッダーのボタンにはアイコンを使ってよい。IBM の Carbon（`@carbon/icons`、Apache-2.0）を使う（書体の IBM Plex と同じ IBM）。SVG の path をコードに写して埋める（`src/icons.rs`。#23）。「アイコンは基本使わない」はヘッダーのボタンを除いて残す
- トップの一文は「構造を計算し、かたちを眺める。」をやめ、`display` で `rustruct.matsumok.com` を置く。スマホのヘッダーが `rustruct` だけになっても、トップでは住所が全部見える。句点の `accent` は使う場所が無くなる
- 本文は**中央に寄せる**。最大幅は2単位で（本文の箱は、2列と区切りの線と線の左右の空きを足した幅。iPad 703px（`max-w-page`）、PC 831px（`lg:max-w-page-lg`）。tokens.json には持たず、`theme.rs` が `width-column` と `space-4`・`space-9` から導く。2026-10-15、#23）、PC の左右の空きは受け入れる（Notes の本文が2単位で約 40 字に収まるので）。いったん「左に寄せる」と記録したが、本人の想定は前から中央寄せだったので置き換えた
- Notes の本文は iPad・PC で2単位（335 × 2 + 溝 16 = 686px）。17px で1行約 40 字。3単位（約 61 字）は長すぎ、1122px 以上でないと入らないので退けた
- ページの左右の余白はスマホ `space-5`（20px）、iPad `space-7`（40px）、PC `space-8`（48px）。ヘッダーは画面の端からこの余白の内側いっぱいに広げ（サイト名は左端、ボタンは右端。GitHub や Vercel の形）、本文の箱はこの余白の内側で中央に置く。本文の箱とヘッダーの端はそろわない。2列には 335 × 2 + 溝 16 + 区切り 17 + 左右 40 × 2 = 783px 要る。768〜782px では列が少し縮むが、この幅の主な機種は無い（iPad mini の縦 744 はスマホの組み方、iPad の縦は 820 から）
- 単位 335px の検証（360px は根拠が無かったので確かめ直した）: 下限は最も広い表（コンクリートの許容応力度の根拠、約 310px）。上限は SE の本文の幅（335）と、768px で2列が入る幅（2u + 溝 16 + 区切りの余白・線 17 + 左 40 + 右 20 ≦ 768 から u ≦ 337）。PC の 1024px で3列を入れるには u ≦ 308 で表が入らないので、列は PC でも2列まで（デザインシステムの「2列まで」と合う）。360px は SE に入らず、最も多い 414px の iPhone では右に 14px の半端な空きを作っていた。iPhone SE 第1世代（320px）は本文 280px に表が入らないので対象外
- 一覧（名前＋一行＋パス）は、スマホは1列（画面いっぱい）、768px から 335px の列を `space-4` の溝で2つ。計算のページの列の間（PC `space-9`）とはそろえない（2026-10-15、#23）
- 縦の余白（セクションの間、トップの一文の上下、表の行など）は画面幅で変えない。縦の余白は 13 / 11px の文字に合わせて決めてあり、その文字は変えないため。余白の上限 48px もそのまま
- **ライトとダークの切り替え**（2026-10-15）: 初めは OS の設定どおり。押すたびにライトとダークが入れ替わり、選んだものをブラウザに覚える（次に開いても同じ色）。一度押すと OS に従う状態には戻らない。OS・ライト・ダークの3つを巡る案は、押しても色が変わらない一押しができるので退けた。覚えない案は、読み込み直すたびに OS の色に戻るので退けた。HTML は WASM より先に描かれるので、覚えた色は `<head>` の小さなスクリプトで描く前に当てる（無いと開くたびに一瞬 OS の色が出る）
- **アカウントのボタン**（2026-10-15）: ログインの仕組み（限定データの最初の Tool、ADR-0002）ができるまでは、形だけ置き、押すと「登録は準備中」と出す。一言はボタンの下に重ねて出し、ヘッダーの並びを動かさない。位置とアイコンは先に決めておき、後で中身を置き換えてもヘッダーの並びは変わらない。置かない案と、`/root/` への入口にする案（今は本人しか通れない）は退けた
- **スマホのメニュー**（2026-10-15）: ヘッダーは残し、その下の画面をまるごと `paper` の面で覆う。中身は四部（名前とパス。今いる部に `accent` の下線）だけ（ライトとダーク・アカウントはヘッダーに残したので、2026-10-15 に外した）。開くとメニューのボタンが × に変わり、× か項目を選ぶと閉じる。開け閉めに動きは付けない。ヘッダーから中身の高さだけ垂れる板の案は、境が線 1 本で本文が透けて見えるので退けた。左から引き出す形は、本文との境に暗い幕か影が要るので候補にしなかった

### エラーと警告
- ページ先頭にエラー件数と場所のまとめ
- セルのエラーは `ng` の 2px 枠。計算できないセルは値を消して「—」
- 入力部品のエラーは枠・ラベル・文言の3つが `ng`
- 警告（計算はできる）は色を使わず「!」と文言のみ

### 使えない状態
- 塗りは変えず、線と文字だけ薄くする（本来は書ける場所だと分かる）
- 無効には必ず理由を添える。使えない項目は隠さず薄くする

### 技術的な前提
- UI は Dioxus（Web 版）。CSS は Tailwind。色は役割名のトークンで持ち、マークアップに色クラスを直接書かない
- 文字の指定は役割（`heading` / `body` / `num` など）で行い、大きさ・太さ・色をまとめて持つ
- コントラストは機械的に検査する。WCAG 比（tokens.json の usage に書いてある 3:1 / 4.5:1）を必須、APCA を警告として出す。検査は Rust のテストとして書く（2026-10-14 決定）
- アニメーションなし。性能に響くことはしない
- 必要な部品：テキスト入力、チェックボックス、コンボボックス（打ち込みもできること）

## グラフ描画ライブラリ（2026-09-30 の設計メモ）

- Rust の単独クレートとして汎用に作る。rustruct はその使い手の一つ。3次元も含める。地図は入れない
- 短期的な成果は気にしない。設計を楽しむ
- 課題図（8枚）：層間変形角図／応答スペクトル（Sa–T）／三軸（トリパタイト）応答スペクトル／必要スラブ厚のコンター／応力のコンター／時刻歴＋履歴ループ＋再生／3次元のモード形／風車タイリング
- 座標変換は matplotlib・Makie 型の2段：非線形の目盛り変換 → アフィン変換。逆変換（当たり判定）も同じ段をたどる
- 描き手に依存しない中間表現（シーン：パス・四角・文字・点の記号・格子の場）を背骨にする。描き手候補は SVG・wgpu・静的 SVG・egui
- 反応性は Dioxus のシグナルに直接依存せず、自前の小さなリアクティブ層を持つ（Makie 型）
- 他ライブラリから持ち帰ること：再計算しても拡大範囲を保つ（Plotly `uirevision` 相当の「表示の世代」番号）／選択はグラフではなくものの ID に付けて共有する（Bokeh）／必要な所だけ計算し直す（Vega）／文字は SVG・データは差し替え層・カーソルは上の層（uPlot）／スマホの拡大は下の範囲バー（ECharts）
- インタラクションの5段階：読み取り・拡大・連動・再計算・再生。2本指の拡大は使わない
- 「軸・格子・等値線をガイドとして統一する」（g(x,y)=c の線の集まり）は議論継続中
- 等値線上の数値は白抜き文字を重ねる方式を既定にした

## エージェントの動き方

- 本人が一歩ずつ自分の手で進める方針。設計の会話では聞かれたことに答え、小さく提案する。実装の単位は Issue 1 本（`CODING_STANDARDS.md`）
- デザインを提案する前に `docs/design/README.md`（デザインシステムの写し）とこの文書を読み、提案が前の決め事とぶつかる所を先に示す（2026-10-14、読まずに勧めて組み直した。`docs/adr/0006`）
- 値は `docs/design/tokens.json` から取る。勝手な色や大きさを足さない
- 決まっている規則に反する提案はしない。反する必要があるなら、どの規則に反するかを明示して理由を添える
- 未決のことを勝手に決めない。候補を出して本人に選んでもらう
- デザインの提案は実在するサイトを参照して、言葉より見た目で示す
- 「導出できる値は保存しない」「不変条件は構造で守る」は UI の状態設計にも適用する
