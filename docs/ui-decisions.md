## 2026-09-30 に決めたこと（要約。本文は `docs/design/README.md`）

### サイトの構成
- 個人サイト。**Tools**（構造計算）・**Studies**（数学やかたちの可視化）・**Notes**（文章）の三部構成
- サイト名はドメインそのもの `rustruct.matsumok.com`。`wordmark`（等幅 12px / 500）で、`.matsumok.com` はドットごと `muted`・400（2026-10-14 に dx serve で見て決定。`accent` にはしない）
- **箱で区切らず、余白と文字の大きさの差で組む。** 灰色の地に白いカードが並ぶ管理画面の型は避ける
- 住所で組む：各項目にパス（`/studies/pinwheel`）を `path` で添え、下層ページでは同じ住所が伸びる。**これがパンくずの代わり**
- 一覧は「名前＋一行＋パス」だけ。グリッドは2列まで
- 参照する温度感：takram、rsms.me、tylerxhobbs.com、Order

### 色（`tokens.json` の役割名）
- 地は `paper` 一色（ライト `#ffffff`）。`fill` は「書けない」と「図の下地」の2つの意味だけ
- 文字は `ink` と `muted` の2段。線は `line`（1px）、入力欄の枠は `line-strong`
- `ng`（Radix red-11 `#ce2c31`）は NG 判定と入力エラーだけ。警告は色を使わず「!」と文言
- 差し色 `accent` は indigo-9 `#3e63dd` の1色相。使う場所は4つに限る（見出しの一文の句点、今いるセクションの下線、新着の点、図の中の一か所）。プライマリーは `ink`（主ボタン・リンク・選択セルは墨）。面を塗る薄い段は `accent-soft`
- ダークテーマは同じ役割名で切り替える。マークアップに色の値を書かない

### グラフの色
- 系列色は5色を先頭から順に：`chart-1` 琥珀（amber-11）、`chart-2` 青碧（cyan-9）、`chart-3` 墨（= `ink`）、`chart-4` 紅（ruby-9）、`chart-5` 青紫（violet-9）。6系列以上はグラフを分ける
- 色覚シミュレーション（Machado・Brettel）と 2px 線での見分けやすさ（Szafir）で総当たり検証済み。岡部・伊藤の約2倍の見分けやすさ。**8月の「indigo・cyan・orange・bronze」は廃止**
- 点の形も系列ごとに変える：● ■ ▲ ◆ ▼
- 一方向の濃淡（コンタ）は藍の `seq-1`〜`seq-12`。正負のある量は藍←灰→琥珀の `div-1`〜`div-12`（0 は div-6 と div-7 の境）
- 図の形は matplotlib 型：`ink` 1px の四辺の枠、内向きの目盛り、格子は既定で引かない。凡例は図の中8か所・外3か所・auto・none。スマホ幅では下
- 制限値の線は `muted` の破線。超過点だけ `ng` にして「NG」の文字を添える
- 2色塗り分け（風車タイリング等）は `accent` と `chart-2`
- wgpu で描くときも同じ sRGB 値を使う

### 文字
- 和文 IBM Plex Sans JP、数字・パス・サイト名 IBM Plex Mono（Google Fonts）
- 大きさは振れ幅で階層を作る：`display` 30px / `title` 22px は細く（300）、それ以外は 13px と 11px。中間を作らない。`figure`（56px / 300）はページの答え1つだけ
- 太字（500）は `heading` と `wordmark` だけ
- 数値は必ず `num`（等幅）で単位まで右揃え。Notes の本文だけ `prose`（15px / 28px）
- 文言は短く言い切る。「！」や絵文字は使わない。見出しは体言止め

### 余白と形
- `space-1`〜`space-8` = 4 / 8 / 12 / 16 / 20 / 28 / 40 / 48px。48 より大きい余白は使わない
- 角は `radius-0` が既定。`radius-8` はボタンとツールの入力カードだけ。`radius-full` は状態の点だけ
- 影、グラデーション、ぼかし、トランジションは使わない

### 図とアイコン
- Studies の図版は計算で描いた SVG。線は `ink` の細線、下地は `fill`
- アイコンは基本使わない。ロゴはない。サイト名は `wordmark` の文字で組む

## 8月から引き継ぐ規則（使い勝手の規則。9月の値で読み替える）

### 入力と表示の区別（最重要）
- 入力表は「データテーブル」ではなく**スプレッドシート**（`Sheet`）。格子は `line`、選択セルは `ink` の 2px 内枠
- 塗り＝書けない、枠＝書ける。書ける場所は `paper` の地に `line-strong` の枠。計算セル・行見出し・列見出しは `fill`
- 枠のある器は入力にしか使わない。結果は `num` で置いて `line-strong` の下線だけ（`ResultValue`）。読み取り専用の入力欄は使わない
- 入力セルは大きく、表示用テーブルは小さく。表示用テーブルの行区切りは罫線（交互の背景色は不採用）
- 入力値を変えた瞬間に派生値（μs級）が更新される。重い解析は即時でなくてよい
- 全画面の再描画はしない。行を1つ足すときも部分更新
- Excel 連携は値のコピペができれば十分

### エラーと警告
- ページ先頭にエラー件数と場所のまとめ
- セルのエラーは `ng` の 2px 枠。計算できないセルは値を消して「—」
- 入力部品のエラーは枠・ラベル・文言の3つが `ng`
- 警告（計算はできる）は色を使わず「!」と文言のみ

### 使えない状態
- 塗りは変えず、線と文字だけ薄くする（本来は書ける場所だと分かる）
- 無効には必ず理由を添える。使えない項目は隠さず薄くする

### 技術的な前提
- UI は Dioxus（Web 版）。CSS は Tailwind。色は役割名のトークンで持ち、マークアップに色クラスを直接書かない
- 文字の指定は役割（`heading` / `body` / `num` など）で行い、大きさ・太さ・色をまとめて持つ
- コントラストは機械的に検査する。WCAG 比（tokens.json の usage に書いてある 3:1 / 4.5:1）を必須、APCA を警告として出す。検査は Rust のテストとして書く（2026-10-14 決定）
- アニメーションなし。性能に響くことはしない
- 必要な部品：テキスト入力、チェックボックス、コンボボックス（打ち込みもできること）

## グラフ描画ライブラリ（2026-09-30 の設計メモ）

- Rust の単独クレートとして汎用に作る。rustruct はその使い手の一つ。3次元も含める。地図は入れない
- 短期的な成果は気にしない。設計を楽しむ
- 課題図（8枚）：層間変形角図／応答スペクトル（Sa–T）／三軸（トリパタイト）応答スペクトル／必要スラブ厚のコンター／応力のコンター／時刻歴＋履歴ループ＋再生／3次元のモード形／風車タイリング
- 座標変換は matplotlib・Makie 型の2段：非線形の目盛り変換 → アフィン変換。逆変換（当たり判定）も同じ段をたどる
- 描き手に依存しない中間表現（シーン：パス・四角・文字・点の記号・格子の場）を背骨にする。描き手候補は SVG・wgpu・静的 SVG・egui
- 反応性は Dioxus のシグナルに直接依存せず、自前の小さなリアクティブ層を持つ（Makie 型）
- 他ライブラリから持ち帰ること：再計算しても拡大範囲を保つ（Plotly `uirevision` 相当の「表示の世代」番号）／選択はグラフではなくものの ID に付けて共有する（Bokeh）／必要な所だけ計算し直す（Vega）／文字は SVG・データは差し替え層・カーソルは上の層（uPlot）／スマホの拡大は下の範囲バー（ECharts）
- インタラクションの5段階：読み取り・拡大・連動・再計算・再生。2本指の拡大は使わない
- 「軸・格子・等値線をガイドとして統一する」（g(x,y)=c の線の集まり）は議論継続中
- 等値線上の数値は白抜き文字を重ねる方式を既定にした

## エージェントの動き方

- 本人が一歩ずつ自分の手で進める方針。大きな実装をまとめて書かない。聞かれたことに答え、小さく提案する
- 値は `docs/design/tokens.json` から取る。勝手な色や大きさを足さない
- 決まっている規則に反する提案はしない。反する必要があるなら、どの規則に反するかを明示して理由を添える
- 未決のことを勝手に決めない。候補を出して本人に選んでもらう
- デザインの提案は実在するサイトを参照して、言葉より見た目で示す
- 「導出できる値は保存しない」「不変条件は構造で守る」は UI の状態設計にも適用する
