# UI の決め事と議論の記録

エージェントへの引き継ぎ用。2026-08 から 2026-10 にかけて決めたこと、見直し中のこと、未決のことを分けて書く。
思想と経緯は `docs/philosophy.md` を先に読むこと。

## 状態の注記（最初に読む）

- 2026-08 に画面の規則を細かく決めた。その後 2026-09 に「少し野暮ったい」と感じ、**ビジュアルの方向性は考え直し中**
- ただし、下の「確定している規則」の多くは見た目のテイストではなく**使い勝手と意味の規則**なので、見直し後も残す前提
- 8月に作った成果物（`tailwind.css`、`check-contrast.mjs`、`components_tw.rs`）はこのリポジトリには入っていない。必要なら規則から作り直す

## 確定している規則

### 技術的な前提

- UI は Dioxus（Web 版が前提。デスクトップ同梱ではない）
- CSS は Tailwind。色は Radix Colors の12段スケールを土台に、`@theme` で役割名のトークンを定義する
- 依存は `@radix-ui/colors`（CSS のみ、JS なし）。スケールは slate（中性）、tomato（判定の朱）、indigo（差し色）
- ダークモードは `@custom-variant dark` の1行だけで切り替える。役割名もマークアップも変更しない
- マークアップに `text-ink` のような色クラスを直接書かない。文字は役割（下記）で指定する
- アニメーションなし。CSS transition・backdrop-filter は使わない。性能に響くことはしない

### 画面構成

- 1ページに1カード
- アプリ名（サイト名）は上のバーに置く。サイドバーが閉じていても常に見える
- ツールの切り替えはサイドバー。カテゴリごとのアコーディオン（既定は開いた状態、増えてきたら閉じる）
- トップにパンくずリスト。親から別のツールへ遷移できる。860px 以上で表示し、スマホ幅では出さない（現在地はページ見出しが持つ）
- タブ＋ページ送り（順番に進む形）は使い方と違うので不採用
- サイト名の表記は等幅で `rustruct` を濃く、`.matsumok.com` を薄く。`.` の色は変えない

### 入力と表示の区別（最重要）

- 入力表は「データテーブル」ではなく**スプレッドシート**として作る。Carbon のデータテーブルは表示前提で入力向きではない
- 色の意味は2つだけ：**白＝書ける／地色＝書けない**。編集できないセル（計算セル・見出し・行見出し）は地と同色
- 格子はスプレッドシートとグラフ（方眼）に引く。表示用テーブルには引かない。表示用テーブルの行区切りは罫線（交互の背景色は不採用）
- 選択セルは黒 2px の内枠
- 入力セルは大きく、表示テーブルは小さく
- 枠のある器は入力にしか使わない。結果は下線だけ引いて値として置く。読み取り専用の入力欄は使わない
- 入力値を変えた瞬間に派生値（μs級の軽い計算）が更新される。重い解析は即時でなくてよい
- 全画面の再描画はしない。行を1つ足すときも部分更新
- Excel 連携は値のコピペができれば十分

### 配色（2026-08 時点の値。テイスト見直しで変わりうる）

冷たい中性。暖色は却下。背景を暗くしない。地と面のコントラストを強くしすぎない。

| 役割 | 値 |
|---|---|
| 地 | `#F2F3F3`（オフホワイト。セクションを白抜き） |
| 白（書ける） | `#FFFFFF` |
| 線 | `#E1E3E4` |
| 強い線 | `#AEB2B4` |
| 文字 | `#17181A`、`#666A6E` |
| 薄い文字（disabled） | `#A9ADB1` |
| NG | `#C4362C`（Radix tomato。13px で読めるよう 11→12 段目に変更済み） |

- 判定の朱は NG・制限値超過にのみ使う
- 差し色（アクセント）は Radix indigo。プライマリーではなく数か所に少量
- グラフ用の色はアクセントとは別に、岡部・伊藤の考え方で選んだ Radix 9段目の indigo・cyan・orange・bronze の4色。アクセントがグラフの1色を兼ねても問題ない。2色塗り分けはアクセントと accent-soft
- グラフは将来 wgpu で描く予定なので、グラフ用パレットは Tailwind 側で細かく詰めない

### 文字

- フォントは IBM Plex Sans JP。数字・ラテンは IBM Plex Mono
- スタックは `"IBM Plex Sans JP" → "Hiragino Sans" → "BIZ UDPGothic" → sans-serif` の1本。Yu Gothic は細く出るので入れない。等幅のフォールバックは SF Mono / Menlo / Consolas
- 配信はまず Google Fonts CDN。グリフ不足や通信制約が出たらセルフホスト（unicode-range 分割）へ
- 文字サイズは3段（11 / 13 / 15px）。階層は色数ではなく太さと濃さで作る
- 文字は役割トークンで指定する：`t-num` / `t-label` / `t-tick` / `t-judge` / `t-off` / `t-title`。トークンは色単独ではなく「大きさ・太さ・色」の3つ組
- ラベルと軸ラベルは太さ 600。軸ラベルは 10px
- コントラストは APCA で機械的に検査する。目標 Lc は大きさ・太さ・読み方（読む／拾う／判別）の関数で算出。検査スクリプトが Radix の CSS から実値を読み、明暗両方を検査して下回れば CI 異常終了

### 寸法

- 余白は 4 / 8 / 12 / 20 / 32
- 線幅 1px
- 角丸：カードと同階層のもの（カード・ボタン）は 8px、カードの中身は 0

### エラーと警告

- 入力エラーと NG 判定は同じ朱。場所（白い入力欄か、読むだけの表か）で区別できる
- セルのエラーは朱の 2px 枠＋行見出しも朱。地は白のまま
- 計算できなかったセルは値を消して「—」
- 入力部品のエラーは枠・ラベル・文言の3つが朱
- ページ先頭にエラー件数と場所のまとめ（左端に朱 2px）
- 警告（計算はできる）は色を使わず「!」と文言のみ。色数を増やさない

### 使えない状態（disabled）

- 色は増やさず、濃さの3段目 `--muted` を使う
- 塗りは変えず、線と文字だけ薄くする（本来は書ける場所だと分かる）
- 使えないチェックはオンでも黒ではなく薄い灰。主ボタンの無効は黒塗りをやめ薄い灰
- 無効には必ず理由を添える
- サイドバーの使えない項目は隠さず薄くする

### 必要な部品

- テキスト入力、チェックボックス、コンボボックス（打ち込みもできること）
- 動きの作り込みは後回し。まず見た目を決める

## 見直し中のこと（2026-09〜）

- 計算ツール集にとどめず、数学の可視化（Pinwheel tiling、二重振り子など）やブログ的なものも置く**個人の総合サイト**にする
- 8月のデザインは少し野暮ったい。ビジュアル先行で考え直す。参照元も広げる
- 参照は用途（建築・解析）に紐づけず、純粋な見た目のテイストとして挙げること
- 好き：rsms.me（「めっちゃいい」）、tylerxhobbs.com、order.design、takram.com、rauno.me、Linear、Dieter Rams / Braun、原研哉
- 違う：maggieappleton.com（ごちゃついている）、qosmo.jp（好きだが重い感じが思想に反する）、craigmod.com（ブートストラップ感）、ciechanow.ski（少し野暮ったい）
- IBM Carbon の見た目は好きだが、そのまま使うのではなく参照として
- 「製図台」コンセプト（パネルが物として紙の上に乗っている）は強く同意していない。不採用でよい
- 色ごとに意味を固定する表を作る案は「やりすぎ」。差し色は少量で十分
- グラフの見た目は matplotlib のものが一番よい。グラフ描画は既存ライブラリに頼らず、汎用クレートとして自作する構想

## エージェントの動き方

- 本人が一歩ずつ自分の手で進める方針。大きな実装をまとめて書かない。聞かれたことに答え、小さく提案する
- 確定している規則に反する提案はしない。反する必要があるなら、どの規則に反するかを明示して理由を添える
- 未決のことを勝手に決めない。候補を出して本人に選んでもらう
- デザインの提案は実在するサイトやデザインシステムを参照して、言葉より見た目で示す
- 「導出できる値は保存しない」「不変条件は構造で守る」は UI の状態設計にも適用する
