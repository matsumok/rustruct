# rustruct — 思想と経緯

## 何のためのものか

- 構造設計者が使う計算ツールを、自分の手で作って公開する場所
- 同時に、数学的な可視化や書きものも置く、個人の総合サイト（rustruct.matsumok.com）
- 仕事の道具であると同時に、作ること自体を楽しむための場でもある。短期的な成果より、設計と学びを優先してよい

## 大事にしていること

### 作り方

- 一歩ずつ、自分の手で進める。仕様を渡して丸投げするより、理解しながら積み上げる
- 言語はできるだけ Rust に寄せる。JS/TS はライブラリとして使うのは可、自分では書かない
- 型を一箇所で定義し、計算・画面・保存で共有する
- 導出できる値は保存しない。保存するのは入力と、再現に必要な条件だけ
- 不変条件は構造で守る。「気をつけて揃える」に頼らない

### 使い心地

- 入力を変えた瞬間に派生値が更新される。構造計算の画面はこれが本当に多い
- 全画面の再読み込みは許容しない。行を1つ足すたびに全部描き直すのは我慢できない
- 重い解析まで即時である必要はない。即時が要るのは軽い派生値だけ
- アニメーションは要らない。性能に響くことはしない
- Excel との連携は「値をコピペできれば十分」

### 見た目

- 白地、冷たい中性のグレー、罫線で区切る表。まだら模様の交互背景は使わない
- 地と面のコントラストは強すぎない。背景を暗くしない
- 色は少なく。差し色は数か所に少量。判定の朱は NG にだけ使う
- 階層は色数ではなく、文字の太さと濃さで作る
- 入力欄と結果の見た目を混ぜない。枠のある器は入力にしか使わない
- 参照したいテイスト：rsms.me、tylerxhobbs.com、order.design、takram.com、Dieter Rams、原研哉。ごちゃついたもの、重いもの、ブートストラップ感のあるものは避ける
- サイト名は等幅で「rustruct」を濃く、「.matsumok.com」を薄く

### 公開と安全

- 使うだけならログイン不要。計算はブラウザ内で完結させる
- 誰でも書き込める経路を自宅のサーバーまで届かせない
- 招待した人向けの保存と、知らない人向けの保存は別の層として考える
- 保存の形式を先に決めておけば、保存先（ブラウザ・ファイル・サーバー）は後から足せる

## 経緯

### 2026-05　Web スタックの試作

React + Vite と Hono（Cloudflare Workers）で、計算核を WASM にする構成を試した。認証と DB まわりで苦労が多く、JS/TS を自分で書く量が増えていくことに違和感があった。

### 2026-07　Rust で写経しながら作り直し

egui と Axum + SQLite で、階の入力・保存・読込までを教材形式で手書きした。この過程で「階は並行配列ではなく構造体の配列で持つ」「解析設定は独立に保存せず結果に埋め込む」「標準波形は同梱し、アップロード機能は作らない」「最初の一本は配信経路まで通す垂直スライスにする」といった判断を ADR に残した。並行して Rust 製フルスタックの topcoat を調査したが、発展途上で採用は保留。

### 2026-08　画面の設計を詰めた

UI は Dioxus の想定で、デザインの規則を細かく決めた。入力表はデータテーブルではなくスプレッドシートとして作る、グレーは「編集できない」の意味にだけ使う、色は Radix のスケールを役割名で使う、文字サイズは3段、角丸はカードだけ、コントラストは機械的に検査する、フォントは IBM Plex Sans JP と Plex Mono。ナビゲーションは上バーにサイト名、サイドバーでツール切替、パンくずは広い画面だけ。

### 2026-09　個人サイトへ広げ、デザインを考え直す

計算ツール集にとどめず、数学の可視化やブログ的なものも置く個人の総合サイトにする方向へ。8月に決めた見た目は少し野暮ったいと感じ、ビジュアル先行で考え直すことにした。差し色は indigo、グラフは岡部・伊藤の考え方で選んだ4色。グラフ描画は既存ライブラリに頼らず、汎用クレートとして自作する構想（3次元も含む）。

### 2026-10　まっさらにして再出発

試験が終わり、実装を再開。7月までの内容は `archive/2026-07-egui` ブランチに退避し、main を空にした。エージェントに実装させる案も出たが、自分で一歩ずつ楽しんで進めることにした。最初に作るのはサイトの骨組み。ログインについては「公開部分は書き込みなし、保存は別の層」という考え方に整理した。

## まだ決めていないこと

- 知らない人にも保存を開くかどうか（開くなら Cloudflare 上に置き、自宅には届かせない）
- デザインの最終形（9月に方向は出たが、見た目の具体はこれから）
- グラフ描画クレートの設計
- 計算カーネルの減衰の扱いや刻みなど、細部は実装しながら決める
