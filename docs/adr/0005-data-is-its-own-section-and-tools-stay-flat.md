# 材料や規格の値は Data という区分に置き、Tools の分野は URL に入れない

サイトに Data という区分を足して四部構成（Tools / Data / Studies / Notes）にする。コンクリートや鉄筋のように、構造設計で参照する値とその導出を示すページは Data に置く（`/data/concrete/`）。Fc から γ や E を出す程度の計算は含めてよいが、Model を持たず保存しないので Tool ではない。

Tools を分野（RC / Steel / Timber / Dynamics）で分け、その下に Tool と参照データを一緒に置く案も比べた（2026-10-14）。分野から探せるのは良いが、材料は分野をまたぐ（コンクリートは S の柱脚でも、鉄筋はアンカーでも使う）ので置き場が決まらず、言葉を材料という独立の文脈（`docs/materials/`）に切った構成とも食い違う。分野は Tools の一覧の見出しとしてだけ使い、URL は平らなまま（`/tools/slab/`）にする。見出しなら名前を変えても Tool を移してもリンクは切れない。

区分の名前は Materials ではなく Data にした。材料に限らず、限定データ（既往の地震波、継手の諸元）も示す場所になりうるため。
