# 保存形式は serde による JSON で、トップレベルに整数の形式バージョンを1つ持つ

Model の保存形式は `rustruct-types` の型を serde で JSON にしたものとし、トップレベルに整数のバージョンを1つ持つ。ブラウザ内保存・ファイル保存・将来のサーバー保存のどこへも同じ JSON を置く。派生値は含めない。バージョンは互換性が壊れる変更のときだけ上げ、古いバージョンを読む変換は `rustruct-types` に置く。

TOML も検討した。人が読め、コメントを書け、git の差分が読みやすい。しかし保存先3つのうち人が読むのはファイルだけで、ブラウザとサーバーでは利点がなく、`Option` の表現や serde の TOML シリアライザの順序制約という実行時にしか分からない制約を引き受けることになる。形式を2つ持つとバージョン管理も2つになる。ファイルを手で編集する使い方は想定に置かない、と決めて JSON に一本化した。

バージョンを持たない案は、2026-07 に `Vec<Story>` への変更で保存 JSON が読めなくなった経験から退けた。
