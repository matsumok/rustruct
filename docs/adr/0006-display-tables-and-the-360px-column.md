# 表示の表は line の横罫だけで組み、本文は 360px の列を単位に並べる

計算のページ（Data と Tool）の表示用の表と結果の置き方、本文の幅を次のように決めた（2026-10-14、Data のコンクリートのページの見た目を直す中で）。決め事の一覧は `docs/ui-decisions.md` の「列の単位と表」、デザインシステムの写しは `docs/design/README.md`。

## 決めたこと

- **本文の1単位は 360px**（tokens の `layout` の `width-column`、`max-w-column`）。スマホの本文（画面 360〜430px から左右の `space-5` を引いた 320〜390px）に合わせた。狭い画面では縮むので、表と図は 320px でも読めるように作り、1単位か2単位に収める。PC では1単位の列を `space-4` の溝で横に並べ、スマホでは縦に積む
- 計算のページは **入力 → 結果 → 根拠** の順に置き、PC では「入力＋結果」と「根拠」の2列にする。入力を変えながら結果を見るので、入力と結果を同じ列で近くに置く。「入力」「結果」「根拠」という部の見出しと区切りは置かない（文字が増えるだけで、並び順と表の見出しで分かる）
- **表示用の表は横罫だけ**。見出しの下と各行の下に `line`。縦罫・塗り・交互の背景は使わない。入力の Sheet（格子と `fill`）と一目で分けるため
- **`ink` の線は部の見出しの上だけ**（デザインシステムの約束）。表の頭と尻に `ink` を引く論文の表の形も考えたが、部の区切りと同じ濃さになって「ここで部が変わる」が弱まるので退けた
- **結果も同じ表の形**で、入力のすぐ下に置く。デザインシステムの `ResultValue`（値の下だけに `line-strong` の下線）は、名前の側で線が切れて見えるのでやめた
- **単位**: 見出しや名前に付くときは括弧付き（「γ（kN/m³）」「許容応力度（N/mm²）」）、数字の後に付くときは括弧なし（「23.0 kN/m³」）。列の単位が揃う表は見出しに、行ごとに単位が違う表（結果の一覧）は値の後に書く。入力の Sheet の見出しも「B（mm）」にする
- 行の上下は `space-2`、セルの左右は `space-3`、表の端の列は端に寄せる。列見出しは `label` の muted、先頭の列は左、数値の列は `num` で右揃え、式の列は `num` で左揃え
- 表や式の名前は上に `heading`（太字・ink）で置く。初めは 11px の muted にしたが、タイトルだと分からなかった
- 注記は表や式の下に箇条で。出典は画面に出さない。コードのコメントと ADR（`docs/materials/adr/`）に書いてあれば足りる
- 画面に出す値は計算に使うものだけ。コンクリートの単位体積重量は E の式で使う γ だけにし、γ₁ は出さない
- 1単位に入りきらない表は、その表だけ横にスクロールする

## 経緯

最初の Data のページは、表ごとに線の濃さ・余白・幅・単位の書き方がばらばらで、結果と根拠の区別もつきにくかった。表の仕組みを決める中で、エージェントがデザインシステム（`docs/design/README.md`）を読まずに「表の頭と尻に `ink`」「単位は括弧」を勧め、一度そのまま組んだ。本人の指摘で、前に決めた約束（`ink` は見出しの上だけ、数字の後の単位）を守る形に直した。デザインの提案は、先に `docs/design/README.md` と `docs/ui-decisions.md` を読み、ぶつかる所を示してからにする（`docs/ui-decisions.md`「エージェントの動き方」）。

デザインシステムの本体は claude.ai のアーティファクト（`docs/ui-decisions.md` の冒頭）にある。この ADR の決め事（`ResultValue` の置き換え、表の部品、`width-column`、単位の書き分け）は、まだそちらに反映していない。
