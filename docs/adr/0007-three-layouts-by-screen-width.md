# 画面幅で3通りに組み、切り替わる幅は 768px と 1024px、本文の1単位は 335px にする

スマホ・iPad・PC のそれぞれで美しく組むことを条件に、画面幅ごとの組み方を次のように決めた（2026-10-15）。決め事の一覧は `docs/ui-decisions.md` の「画面幅」、表と列の決め事は `docs/adr/0006`。

## 決めたこと

- **切り替わる幅は 768px（スマホ → iPad）と 1024px（iPad → PC）**。Tailwind の `md:` と `lg:` で、既定と同じ名前・同じ値。tokens.json に px で書き、既定の sm・xl・2xl は消す。決めた2段しか書けないようにするため
- **本文の1単位は 335px**。表と図を収める約束の幅で、スマホでは列を画面いっぱい（335〜400px）にし、iPad・PC では列の幅になる。列はどの画面でも2列まで。一覧（名前＋一行＋パス）も 768px から 335px の列を2つ並べる
- **画面幅で大きさを変える文字は、大きな文字と Notes の本文だけ**。768px から約 1.2 倍にし、大きさ / 行送りは display 36 / 48、title 26 / 36、figure 64 / 64、prose 17 / 32。本文・表・ラベル（13 / 11px）と縦の余白はどの幅でも同じ
- **画面はヘッダーと本文に分ける**。ヘッダーは上に固定し、スクロールするのは本文だけ。ヘッダーは左右の余白（スマホ 20px、iPad 40px、PC 48px）の内側いっぱいに広げ、左にサイト名、右にライトとダークの切り替え・アカウント。スマホではサイト名を `rustruct` だけにし、四部へはメニューから行く（メニューのボタンはサイト名の左。切り替えとアカウントはスマホでもヘッダー）。2026-10-15、#23 の後に直した: 初めに書いた「右にページ名・四部のボタン」は本人の意図と違っていたので、ページ名と四部をヘッダーから外した。今いる場所はサイト名の右のパンくずで示す予定（別の Issue）
- **本文は中央に寄せ、最大幅は2単位**（686px）。本文の箱は、2列と、間の区切りの線（1px）と線の左右の空きを足した幅で、iPad は空き `space-4` で 703px（下の 783px の計算と同じ）、PC は空き `space-9`（80px）で 831px。区切りは列の外の独立した要素にし、空きは並べる親の間で決める（2026-10-15、#23。PC の 16 は2列が真ん中に寄りすぎて見えたので、48・64・80・96 を撮り比べて本人が 80 に決めた）。Notes の本文は iPad・PC で2単位、17px で1行約 40 字。本文の頭のパスとページの見出しは残す
- トップの一文は `rustruct.matsumok.com` にする。ヘッダーのボタンにはアイコンを使ってよく、IBM の Carbon を候補にする。ロゴは作らない

## 理由

**切り替わる幅**: Tailwind・Bootstrap・GitHub Primer で最も多い 768px と、各社が 990〜1070px に置く PC の境から取った（Material 3 は 600 / 840、apple.com は 735 / 1069）。iPad mini の縦（744）はスマホ、iPad・Air・Pro 11" の縦（820〜834）は iPad、iPad Pro 13" の縦（1024）と iPad の横（1133〜1366）は PC の組み方になる。rem にしなかったのは、文字を px で固定しているので、ブラウザの設定で切り替わる幅だけが動いてもかみ合わないため。

**1単位を 360px から 335px に**: 360px は「スマホの最初の幅を1単位に」という感覚で決めていて、確かめると次の条件から外れていた。

- 下限: 最も広い表（コンクリートの許容応力度の根拠、約 310px）が入ること
- 上限: iPhone SE（第2・第3世代、画面 375px）の本文の幅 335px に入ること（本人の条件）。768px で2列が入る幅（2u + 溝 16 + 区切り 17 + 左右の余白）
- 360px は SE に入らず、日本で最も多い 414px の iPhone（StatCounter、2026 年 9 月で 23%）では、上限で止まって右に 14px の半端な空きを作っていた

335px は SE の本文の幅そのもので、「SE で確かめた表は、iPad・PC でも同じ幅で出る」と言える。320px も候補にしたが、確かめる幅がどの画面にも現れない。PC の 1024px で3列を入れるには u ≦ 308 で表が入らないので、列は PC でも2列まで（デザインシステムの「2列まで」と合う）。iPad の左右 40px では2列に 783px 要り、768〜782px だけ列が少し縮むが、この幅の主な機種は無い。iPhone SE 第1世代（320px）は本文 280px に表が入らないので対象外。

**文字**: PC で全体を一段上げる案（13 → 14px など）も考えたが、列幅と表を決め直すことになる。大手の多くは本文を固定して大見出しだけ変える（Bootstrap の RFS は小さな文字を縮めない。apple.com も本文は同じ大きさ）。Notes は読みものなので、長文のサイトにならって本文も上げる。大きさは1つの役割に2つまでにした（デザインシステムの「中間の大きさを作らない」）。1.35 倍の案は、title がスマホの display と同じ大きさになるので退けた。

**本文の位置と空き**: 問答の途中で「左に寄せて左の余白を広げる」をいったん選んだが、本人の想定は前から中央寄せだった。PC の左右の空きは、Notes の本文が2単位で読みものの普通の字数（約 40 字）に収まるので受け入れる。3単位の本文（約 61 字）は長すぎ、1122px 以上でないと入らない。

## 残っていること

- ライトとダークの切り替えの動き、ログインができるまでのアカウントのボタンの見せ方、スマホのメニューを開いた形は、2026-10-15 に決めた（`docs/ui-decisions.md` の「画面幅」）。Carbon のアイコンは、Apache-2.0 の path を Rust のコードに写して埋めた（npm も実行時の読込も要らない。`crates/rustruct-web/src/icons.rs`、ライセンスの写しは同じ所の `icons/LICENSE`。#23）
- 実装（tokens.json の切り替わる幅と文字の大きさ、`theme.rs` の生成、ヘッダーと本文の組み直し）は Issue で行う
- デザインシステムの本体（claude.ai のアーティファクト）には、まだ反映していない
