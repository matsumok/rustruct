# 表示の表は line の横罫だけで組み、本文は 335px の列を単位に並べる

計算のページ（Data と Tool）の表示用の表と結果の置き方、本文の幅を次のように決めた（2026-10-14、Data のコンクリートのページの見た目を直す中で）。決め事の一覧は `docs/ui-decisions.md` の「列の単位と表」、デザインシステムの写しは `docs/design/README.md`。

## 決めたこと

- **本文の1単位は 335px**（tokens の `layout` の `width-column`、`max-w-column`）。表と図を収める約束の幅で、1単位か2単位に収める。スマホでは列を画面いっぱいにし、iPad・PC（768px〜）ではこの幅の列を `space-4` の溝で横に並べる。初めは「スマホの最初の幅を1単位に」と 360px にしたが、根拠が弱かったので 2026-10-15 に確かめ直し、iPhone SE（画面 375px）の本文の幅 335px に変えた。検証と画面幅ごとの組み方は `docs/adr/0007`
- 計算のページは **入力 → 結果 → 根拠** の順に置き、PC では「入力＋結果」と「根拠」の2列にする。入力を変えながら結果を見るので、入力と結果を同じ列で近くに置く。「入力」「結果」「根拠」という部の見出しと区切りは置かない（文字が増えるだけで、並び順と表の見出しで分かる）
- **表示用の表は横罫だけ**。見出しの下と各行の下に `line`。縦罫・塗り・交互の背景は使わない。入力の Sheet（格子と `fill`）と一目で分けるため
- **`ink` の線は部の見出しの上だけ**（デザインシステムの約束）。表の頭と尻に `ink` を引く論文の表の形も考えたが、部の区切りと同じ濃さになって「ここで部が変わる」が弱まるので退けた
- **結果も同じ表の形**で、入力のすぐ下に置く。デザインシステムの `ResultValue`（値の下だけに `line-strong` の下線）は、名前の側で線が切れて見えるのでやめた
- **単位は表の名前か列の見出しに括弧で書き、数字の後には付けない**。単位の違う値を並べる結果（γ と E）は、値ごとに列を立てて見出しに書く。入力欄の名前と入力の Sheet の見出しも同じ（「Fc（N/mm²）」「B（mm）」）。途中で「数字の後は括弧なし」を混ぜたが、ページの中で単位の置き場が散らばって読みにくかったので一本にした。デザインシステムの「単位まで含めて右揃え」はこれで置き換える
- 「入力＋結果」の列と、入力に依らない表や式の列の間には `line` の区切りを引く。区切りは列の外の独立した要素で、線の左右の空きは並べる親の間（iPad `space-4`、PC `space-9`。`docs/adr/0007`）。スマホで縦に積むときの区切りの上下は `space-8`。`space-7`（40px）は表の行の高さとほぼ同じで、区切りが表の最後の行の罫に見えた（2026-10-15）
- 行の上下は `space-2`、セルの左右は `space-3`、表の端の列は端に寄せる。列見出しは `label` の muted、先頭の列は左、数値の列は `num` で右揃え、式の列は `num` で左揃え
- 列見出しは折り返さず、改行は `br` で決める。数値の列の見出しを2行にするときは、行どうしを左で揃え、まとまりを列の右（数値の右端）に寄せる。初めは行ごとに右揃えにしていたが、2行の左端がずれて読みにくかった（2026-10-15、本人が撮り比べて決めた）。自動の折り返しでは「せん断補／強」のように語の途中で切れた
- 列をまとめる見出し（鉄筋の許容応力度の「長期」「短期」）は、またがる列の中央に置き、下に `line` を引く。線はまとまりごとに `space-3` 離す。先頭の列の見出しは2行にまたがる。2行の見出しと並ぶ1行の見出し（「呼び名」「種類」）は上下の中央に置く（2026-10-15。初めは下の行に寄せた）
- 括弧書きを添える値（表 6.2 の「215（*195）」）は、括弧書きを隣の列に分け、括弧の外の数値を括弧の無い行の数値と右端で揃える（2026-10-15）
- 4桁以上の数は3桁ごとに「,」で区切る（公称断面積の「1,140」。2026-10-15）
- 小数の桁数が行で違う列は、小数点の位置を縦に揃える。足りない桁（と小数点）を数字幅の空白（U+2007）で右に埋め、読み上げから外す（`aria-hidden`）。CSS に小数点で揃える機能が無く、整数部と小数部を別のセルに分ける案は、1つの数が2つのセルに割れてコピーすると列が分かれるので退けた（2026-10-15）
- 表や式の名前は上に `heading`（太字・ink）で置く。初めは 11px の muted にしたが、タイトルだと分からなかった
- 注記は表や式の下に箇条で。出典は画面に出さない。コードのコメントと ADR（`docs/materials/adr/`）に書いてあれば足りる
- 画面に出す値は計算に使うものだけ。コンクリートの単位体積重量は E の式で使う γ だけにし、γ₁ は出さない
- 1単位に入りきらない表は、その表だけ横にスクロールする

## 経緯

最初の Data のページは、表ごとに線の濃さ・余白・幅・単位の書き方がばらばらで、結果と根拠の区別もつきにくかった。表の仕組みを決める中で、エージェントがデザインシステム（`docs/design/README.md`）を読まずに「表の頭と尻に `ink`」「単位は括弧」を勧め、一度そのまま組んだ。本人の指摘で、前に決めた約束（`ink` は見出しの上だけ、数字の後の単位）を守る形に直した。デザインの提案は、先に `docs/design/README.md` と `docs/ui-decisions.md` を読み、ぶつかる所を示してからにする（`docs/ui-decisions.md`「エージェントの動き方」）。

この ADR の決め事（`ResultValue` の置き換え、表の部品、`width-column`、単位の書き分け）は、当時デザインシステムの本体だった claude.ai のアーティファクトに反映しないままだった。2026-10-23 に正本をリポジトリにしたので、反映は要らなくなった（`docs/adr/0012`）。ファイル名は初め `0006-display-tables-and-the-360px-column.md` だった。
