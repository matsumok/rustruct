# SeismicModelは並行VecではなくVec<Story>で階を持つ

当初SeismicModelは階ごとの値を3本の並行Vec(story_masses / story_stiffnesses / story_heights)で持っていたが、Story構造体(mass / stiffness / height)のVecに変更する。storiesは最下層(1F)をindex 0として下から上へ並び、階番号はindexから導出する。floor_numberのようなフィールドは持たない。

理由: UIの階追加・削除機能の実装中に、「3本のVecは常に同じ長さ」という不変条件がどこにも守られておらず、push/removeを1本分書き忘れるだけで静かに壊れる(UIのpanic、または計算結果の欠落)ことが露見した。Vec<Story>ならこの不変条件は構造的に壊せない。計算カーネル側は列(質量ベクトル等)が欲しいときにstoriesからmapで抽出する手間が1つ増えるが、些細なコストと判断した。階番号を持たないのは同じ原理による — 番号の正体はVec内の位置であり、独立に持てば削除時の振り直し漏れでズレうる。導出できる値は保存しない(階数をフィールドに持たないのと同じ判断)。

影響: 保存JSONの形が変わるため、既存の開発DBのdataカラムは読めなくなる。未デプロイ(マイグレーション凍結前)のため開発DBの破棄で対応する。デプロイ後にこの変更を行う場合はデータ移行が必要だった。
